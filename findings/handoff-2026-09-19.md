## The one lever that worked, and its precise shape

**Removing in-graph torch glue between kernels pays; merging kernels does not.**
- The key offset was 9 torch ops per layer (5 fwd + 4 bwd) on 16 MB tensors between the pre kernel and the attention.
  Folding it *into* the existing kernels (a PE matmul against constant 0/1 shift matrices, carry across 128-row tiles;
  bit-exact on device) bought **+3.4% throughput** (I_KO1 581 vs I_KO0 562 steps / 300 s) and **-0.0017** at 1800 s.
- Padded ZeRO sharding of the two (12, ...) MLP stacks (12 -> 16 over 8 ranks, 2 matrices each instead of 12 replicated
  Muon per rank; bit-identical math) bought **+1.1%** (I_PAD1 566 vs I_PAD0 560).
- **But** `layer_fwd_fused` (one kernel = pre + nested vendor attention + post; all 13 outputs bit-exact on device,
  **-9.1% standalone**: 7.413 vs 8.156 ms per layer forward) **LOST in the full graph**: G_FUSED 0.978632 with 3462 steps
  vs G_KOPAD 0.977482 / 3547 = the step got ~2.4% **slower**. The compiled graph was overlapping the three separate
  kernels better than the fused one runs internally. Kernel-count reduction is not the lever; glue-op removal is.

## Closed 2026-09-16/17, each with its number (do not re-litigate)

- **Lever F (optimizer/comm overlap): impossible on this runtime.** `experimental/neuron/cc_overlap_probe.py` (F_PROBE):
  an async reduce_scatter/all_gather issued before a 2.9 ms matmul loop costs exactly the sum, at 50 MB (1.16+2.94=4.10),
  537 MB (9.47+2.93=12.30) and all_gather (1.09+2.98=4.09); two async collectives back to back do not pipeline either.
- **Lever D (multi-hop): dead at fixed time.** The K/V-reuse kill test passed locally (R_HOPKV 1.183902 == R_HOP 1.183924,
  so reuse keeps the whole quality gain), but the decision gate F_HOP44 (full-recompute fused hop on the v44 base) scored
  **0.985652** (+0.0065, 2857 steps). A 30%-cheaper hop cannot close that.
- **Depth 14:** 0.981142 (+0.0020, 3022 steps at 0.58 s). Survived without an OOB (1 of 3 depth-14 runs ever has).
- **Data/packing axis exhausted:** best-fit-decreasing packer with 100% coverage +0.0025 (the long-document tails the
  provided packer drops are worth dropping); all-rows-mid-document +0.0006; drop docs > 4097 wash, > 2048 +0.0033;
  re-cut the second pass wash. The provided best-fit packer at PACK=4 is the optimum of everything tried.
- **Free-startup-window ideas (compile-window-and-packing.md Theme A):** host path is 20.8 ms of a 446 ms micro-step
  (H_PROF2) and already overlaps the backward -> ceiling ~0.001. SYNC_EVERY batching: 560/564/566 steps at 1/4/8 = nothing.
- **Tile pipelining (ideas-2026-09-16 #1):** nki 0.5.0 has no public pipelining construct (`affine_range` etc. are plain
  `range`; the real API is internal), and it is not needed: fused MLP auto-allocated 1.475 ms vs hand-placed 3-deep ring

  log-softmax/gather blocks) -> 5 steps trained. Closed on compile cost.
- **NEFF (`findings/neff-format.md`):** neuronx-cc emits a gzip'd tar with one instruction stream per engine (Pool 405 MB,

## The bug that invalidated six earlier verdicts

`findings/ema-cold-start-bug.md`: on a **cold short screen** the step-0 `elapsed_frac` still contained the compile time
(the budget clock restarts only at the end of the excluded startup step), so a compile >= 0.85 x budget started the tail
EMA at step 0 and wrecked the checkpoint (600 s screens +0.07, 300 s +0.14). Fixed in v44+ and in the vehicle.
**Retracted:** "-O3 / any NEURON_CC_FLAGS corrupts the eval graph" (they are merely useless), "the glue hoist corrupts
eval", "HDC binding +0.098" (honest re-measure: +0.013, still loses), and probably the multi-hop "eval collapse".
**Rule:** on every short screen check the log line `EMA of the weights started at step N` - N must be ~0.85 x num_steps.

## Where the remaining ideas stand

1. **More glue removal** (the only lever with evidence behind it). The key-offset fold proved the mechanism; audit the
   remaining per-layer torch ops the same way, especially in `_bwd_impl` (the dsink reduction, the `out`/`dy4`
   permute-reshape pairs, the XSA-off branches) and in the eager sidecar path. Each op removed is ~0.3-0.5% of the step.
   Method: a paired 300 s screen (glue vs kernel) first, then one 1800 s gate.
2. **The OOB flake root cause is still open.** H1 (lazy H2D copy of a freed host buffer) is falsified - E_POISON, which
   overwrites every plan buffer right after upload, ran clean. The clamped kernels (v45+) make a stray index harmless,
   so it can no longer kill a run; the remaining hypotheses are in `levers-def-2026-09-16.md` (offset views materialised
   by wrap_nki, ring depth, an intra-kernel DMA->DGE race).
3. **Nothing else measured reaches the leaders.** They sit at ~0.958-0.974 portal (~0.951-0.967 local); v46 is ~0.982
   portal. Closing that needs a different regime, not another few thousandths; no candidate is in hand.

## Method rules this campaign paid for

- Judge only by 1800 s gates (same-config band ~0.0004, every run is same-seed/same-order so comparisons are paired);
  600 s screens over-favour high LR, and fixed-step local gains invert at fixed time (confirmed 5x).
- Never ship the vehicle while a queue has unlaunched lines; per-run filenames + `FILE=` (the NKI tracer re-reads source
  at trace time, including at the end-of-run eval trace).
- Queue-line field order is `<ID> <secs|full> ENV=..`; the Bash tool is zsh - generate lines with printf and verify.
- Never run `prepare.py eval-public` standalone on the box (hangs); re-score by training runs.
- `trn2_run.sh` gates on zero trainer procs AND zero `neuron-ls` owners; use bracket pgrep patterns (`[t]orchrun`) over
  ssh or the check self-matches the wrapper.
- Strided-pattern DMAs on graph-produced tensors are unsafe in-graph (rule #11); matmul-against-constant is the safe way
  to shift rows inside a kernel (rules #12/#13 in memory `nki-tracer-rules`).
