# Lazy AdamW for the bigram table (LAZY_BTE), 2026-09-28

## Measured off-device (real shards, host hash bit-identical to the sidecar's, 8 simulated ranks x 16 x 1024)

- **Touched rows per 131,072-token step: 62.5k of 262,144 = 23.9%** (min 57.3k, max 64.6k over 300 steps).
  Per rank's ZeRO shard (32,768 rows): ~7.8k touched (24%), evenly spread (max 7.9k, min 7.7k).
- Turnover: 42% of a step's rows were also touched the step before; gap since a row's last touch has median 2,
  mean 4.2, p90 10 steps. Every row is touched within 300 steps; at any moment 98.6% were touched in the last 50.
- **Every 128-row tile holds ~31 touched rows** (hashing spreads them uniformly; P(tile untouched) = 0.76^128 ~ 0).
  So a kernel cannot save work by skipping tiles. The only way to save time is to gather and scatter single rows.

## Cost of the bigram update (derived, not measured)

AdamW measured 5.2 ms/step (v55 OPTPROF). Its sharded params are bte 134.2M + 4 token tables 16.8M + lm_head 4.2M =
155.2M, so bte is 86% of it: **~4.5 ms**. (The "27.3M elements/rank" in step-split-2026-09-26.md is the whole ZeRO set
including Muon, not AdamW alone.) A lazy, row-indirect kernel could save at most 76% of that, ~3.4 ms, about -0.00027,
before indirect-DMA overhead. It would also need every rank to know the touched rows from all 8 ranks' tokens, which is
an extra collective. **Not built.**

## The quality question: momentum is re-timed, not cut

Under dense Adam, a gradient's momentum (beta1 = 0.8) is spent over the next ~5 *steps*. Under lazy Adam it is spent
over the next ~5 *touches* of that row, so the total displacement per gradient is the same. What differs: (1) the update
lands later (mean gap 4.2 steps) and at the later, lower warmdown LR; (2) the second moment does not decay between
touches (0.99^4, about 4%); (3) momentum still pending at the end of training is never applied; (4) untouched rows skip
weight decay (lr*wd, negligible). This is second-order, so expect a small effect in either direction.

## Implementation (flag, off by default)

`NEURON_COMPETITION_R1_LAZY_BTE=1` in `submission_raw/train3_canon.py`. The table stays dense, so no index plumbing is
needed. `adamw_lazy_kernel` builds a per-row mask from max(g*g) > 0 and folds it into per-row decay, beta and lr
factors. Untouched rows come out bit-exact, and it adds one row-reduce per tile. The reduced gradient of an untouched row
is exactly zero (zeroed buffer, scatter writes only touched rows, and the average of zeros is zero). There is a torch
path for CUDA/CPU. Bias correction uses the global step, as torch SparseAdam does.
- Simulator (`nki/nki_adamw_lazy_test.py`, which tests kernel text extracted from the vehicle): untouched rows are bit-exact.
  With every row touched, the output equals `adamw_kernel` bit for bit.
- Off = unchanged (CPU, 6 real steps, full model): the per-step hex-float losses and the final-weight SHA-256 are identical
  between the pre-change file (run twice) and the flag-off file. Flag on changes the losses from step 2.
- Device-unproven op: `tensor_scalar(op0=nl.greater)`. `NKI_STRICT` makes a lowering failure fatal.
