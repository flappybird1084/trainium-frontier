## 5. NKI attention - the next lever (scoped, test pending)
Vendor kernels in the venv: `nkilib.core.attention.attention_cte` (fwd) and `attention_bwd`, callable from torch via
`from torch_neuronx.nki_hop import wrap_nki; f = wrap_nki(kernel); out = f[grid](...)`, grid = `(int(get_logical_neuron_cores()),)`
(works eager and under torch.compile; the dynamo backend's own SDPA lowering in
`torch_neuron_eager/torch_neuronx/neuron_dynamo_backend/decompositions.py` `_compute_attention_nki` / `_compute_attention_backward_nki`
is the reference for layouts).
- fwd: `attention_cte(q (B*H,L,E), k (B*H,S,E), v (B*H,S,E), tp_q=True, tp_k=True, scale, causal_mask=True, cache_softmax=True,
  bound_min, bound_max, sink)` -> `(out (B*H,L,E), neg_max, out_sum_recip)`; `lse_tiled = -(neg_max + log(out_sum_recip))`
  is (B*H, 128, L/128). **bound_min/bound_max (B*H, L, 1)** = per-query [start, end) KV range = our document mask
  (bound_min = doc start, bound_max = doc end; causal applied on top). **sink (B*H, 1) fp32** = a per-(row, head) logit added
  to the softmax denominator only. seqlen must be a multiple of 128; bf16 inputs, fp32 softmax.
- bwd: `attention_bwd(q (B,H,E,L), k (B,H,E,S), v (B,H,E,S), o (B,H,E,L), dy (B,H,E,L), lse (B,H,128,L/128), sinks_ref (B,H),
  bound_min, bound_max, use_causal_mask=True, mixed_precision=True, softmax_scale)` -> dq, dk, dv (transposed layouts) and
  **dsinks (B,H)** when sinks_ref is given. (bound shapes for the bwd are not documented: read `validate_inputs` in
  `nkilib/core/attention/attention_bwd.py` or let its kernel_assert message tell you.)
- Modelling change required: our 4 learned k/v registers (values contribute to the output) become one learned sink logit per
  (layer, head). 3090 ledger: sinks with zero values were -0.0213 (E23); learnable values added only -0.0029 (E23b) -> cost <= ~0.003.
  Keep a `SINK_MODE` so the explicit path can implement the same denominator-sink math for CPU/CUDA evals and the causality check.
- Test script `nki_attn_test.py` (box `~/tf`, run `NEURON_LOGICAL_NC_CONFIG=2 PYTHONPATH=~/tf python nki_attn_test.py`): B=2 numerics
  vs an explicit fp32 reference (out, dq, dk, dv, dsink max-abs errors) + B=8 timing of fwd+bwd, explicit vs NKI, eager.
  Result goes to `runs/nki_attn_test.log`. DECISION RULE: if NKI fwd+bwd is not at least ~2x faster than explicit at B=8/H=4/L=1024/E=128,
  attention is not where the step time goes and the next kernel target is the MLP / launch count instead.
- Integration plan (vehicle): `ATTN=nki` -> `NKIDocAttention(torch.autograd.Function)` in `CausalSelfAttention.forward`: inputs
  q,k,v (b,h,t,d) after RoPE/QK-norm, bounds computed once per forward in `GPT.forward` from `docs = (idx == BOS_ID).cumsum(1)`
  (doc start/end per position, expanded over heads, int32), sink from a new `block_scalars["sink"]` (L, H) zero-init in the
  scalar AdamW group; forward saves q,k,v,out,lse; backward calls attention_bwd and returns dq,dk,dv,dsink. Fall back to the
  explicit path when `not q.device.type == "neuron"` (eval-public on CUDA/CPU) using the same denominator-sink math.
  Then: screen at 512 compile+LNC=2 (600-900 s, cold compile) and eager 8-way; full run if step time drops materially;
  freeze v12 (portal shape) only after a T14/T20-style validation AND a fresh-process eval-public with the NKI path on the box
  (`python prepare.py eval-public --train-py <file> --checkpoint <ckpt>` on the device) plus `prepare.py check`.
- Risks: the portal scorer imports the file in a fresh process on a Neuron device - nkilib/torch_neuronx imports are fine there
  (same stack), but keep every NKI import guarded and the explicit fallback intact; `check_submission` forbids eval/exec/compile/
  os.system/subprocess/socket - `wrap_nki` is a normal import. Checkpoint format changes (sink param) - `load_for_eval`
  rebuilds from `model_config`, add `sink_mode` to GPTConfig like `use_trigram`.
- After attention: a fused MLP (c_fc + relu^2 + c_proj, fwd+bwd) is the next NKI target; the vendor lib has
