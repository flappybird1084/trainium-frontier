## What was established (Sep 12-13)
1. **Flow works at fixed steps (local GPU):** multi-hop attention (#14: extra weight-tied attention reads, query rebuilt from
   the updated x) + prehead denoising (#6) = -0.0083 at depth 12/500 steps (1.180481 vs 1.188775). Single hop keeps ~90%;
   every-other-block ~93%; detached hop weights ~67%. Output-side logit flows, stack recurrence, latent scratchpad: wash/worse.
   Judge only by eval bpb (training samples few hops, eval uses max).
2. **Trn2 port (compiled v40 path):** hop as compiled eager glue = 1.57-14.5 s/step (dead end: compiler-generated attention
   ~170 ms/hop; stacked-weight autograd scatter; dtype mix NCC_INKI016). Hop as a **fused custom op** built inside
   `build_layer_ops` (pre-attn kernel -> vendor attention -> out-proj; bwd = attention_bwd -> pre_bwd_k with pass-through
   zeroed; ve term + weight grads through the same grad-carrying `ws` casts as the layer op) = **0.62 s/step at DB16**
   (+15% vs v40 0.53), forward verified == eager hop to ~1% on trained weights (RUN_CHK).
3. **Eval collapse root cause = the tail-EMA weight blend.** Hop-trained weights + EMA_BLEND 0.35 -> 1.179; pure EMA + hop
   off -> 1.154; **EMA_BLEND 0 -> 1.063662; 0.1 -> 1.063084**. A hop-coupled net is hypersensitive to weight perturbation
   (same weights read twice); blending live and ~150-step-lagged EMA snapshots lands off-manifold. Eval with MORE hops than
   trained is also broken on the box (1.155) though harmless in the eager path; keep eval = train hops on the box.
4. **Fixed-time verdict so far:** at 600 s the hop loses by 0.010 to a matched reference (18% fewer steps outweigh the
   fixed-step gain). Prehead denoise on the box is a loss (+0.006) and only -0.0011 locally at depth 12: dropped.

## Rules learned (also in memory / findings)
- Never run `prepare.py eval-public` standalone on the box with the kernel env: it hangs (lost 2.5 h). Re-score via a
  training run + `FLOW_EVAL_HOPS`.
- `trn2_job.sh` gate self-matches any job command containing the vehicle path (always "GATE BLOCKED"); `trn2_run.sh`
  refuses (does not wait) on a busy device; queue-runner launch shells must not contain `python`/`torchrun` in their cmdline
  (`[p]attern` trick; write the queue file first, launch the runner from a separate clean ssh).
- Never overwrite the box vehicle while a queue has unlaunched lines (they pick up the new source; compile cache is source-keyed).
- Local `gpu_gdn.sh`: host vmem cap is `R1_VMEM_KB` (48 GB needed for depth-12 multi-hop eval); multi-hop trains at DB=2.
